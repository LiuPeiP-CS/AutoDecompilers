# AutoDecompilers: CIM-v2-pro

Hello everyone!

We present **AutoDecompilers**, an intelligent decompilation agent family. Following our previous **CIM** project, we now introduce **CIM-v2-pro**, which includes two categories of models across three different parameter scales (**[1.3B / 6.7B / 30B](https://huggingface.co/AutoDecompiler)**):

- **End-to-End Models**: directly perform decompilation from assembly code;
- **Refinement Models**: further improve and refine the outputs generated by traditional decompilers.

The framework is designed to support researchers with diverse requirements in binary analysis, reverse engineering, and LLM-based decompilation research, enabling flexible model selection and deployment under different computational budgets and experimental settings.

---

# Overall Framework

Our framework is organized into three major stages: **Supervised Fine-Tuning (SFT)**, **Group Relative Policy Optimization (GRPO)**, and **Multi-Turn Group Relative Policy Optimization (MTGRPO)**.

The **SFT** stage aims to identify the optimal supervised initialization models. Using **LLaMA-Factory**, we fine-tune models on both the *Assembly-to-Source(e2e)* and *Pscode-to-Source(ref)* datasets, resulting in the following checkpoints:

- `1.3B-e2e-sft`
- `1.3B-ref-sft`
- `6.7B-e2e-sft`
- `6.7B-ref-sft`
- `30B-e2e-sft`
- `30B-ref-sft`

The primary objective of the **GRPO** stage is to evaluate the effectiveness of vanilla GRPO optimization setting by training and benchmarking the following models:

- `1.3B-e2e-grpo`
- `1.3B-ref-grpo`
- `6.7B-e2e-grpo`
- `6.7B-ref-grpo`
- `30B-e2e-grpo`
- `30B-ref-grpo`

Building upon GRPO, the **MTGRPO** stage introduces multi-turn reinforcement learning to iteratively refine the decompilation process, producing the following models:

- `1.3B-e2e-mtgrpo`
- `1.3B-ref-mtgrpo`
- `6.7B-e2e-mtgrpo`
- `6.7B-ref-mtgrpo`
- `30B-e2e-mtgrpo`
- `30B-ref-mtgrpo`

For evaluation:
- **SFT** and **GRPO** models are assessed using single-pass inference and validation.
- **MTGRPO** models additionally preserve the complete decompilation-and-repair trajectory for multi-turn analysis.

# SFT Stage (LLaMA-Factory)

## Step 1. Data Preprocessing

The preprocessing pipeline is implemented in:

```bash
/LLaMA-Factory-main/rewrite4ll.py
/LLaMA-Factory-main/rewrite4ll4ref.py
```

The processed datasets are generated as:

```bash
data/cim_plus_dec_dataset.jsonl
data/cim_plus_dec_dataset_ref.jsonl
```

---

## Step 2. Supervised Fine-Tuning

Model training is conducted using the configuration files under:

```bash
FORCE_TORCHRUN=1 llamafactory-cli train /examples/train_full/*_sft.yaml
```

---

## Step 3. Model Selection

We adopt a dedicated `train_examples/Select*` module to identify the top-performing checkpoints for each model scale.

This stage includes:

- dataset reconstruction,
- large-scale inference,
- metric computation and comparison.

---

## Step 4. Evaluation

The evaluation input follows the original CIM data format, with the only modification being conversion into the conversational `message` format.

# GRPO Stage (`trl-main`)

## Step 1. Reinforcement Learning Data Construction

The RL training datasets are generated using:

```bash
train_examples/DataProcess/jsonl_data4rltrain*.py
```

which transforms the original samples into RL-compatible data containing:

- `"prompt"`
- `"source"`
- `"dependency"`

---

### Assembly-to-Source(e2e) Training Data

`jsonl_data4rltrain4end2end.py` constructs a dataset of 10k samples:

- O3: 4000
- O2: 3000
- O1: 2000
- O0: 1000

Filtering criteria include:

- graph node count within `(1, 10)`,
- total sequence length (`prompt + dec_token`) satisfying:
  - `< 4096` for `1.3B` and `6.7B`,
  - `< 65536` for `30B`.

This process generates:

```bash
rl4096train4end2end
rl65536train4end2end
```

---

### Pscode-to-Source(ref) Training Data

`jsonl_data4rltrain4ref.py` similarly constructs two RL datasets:

```bash
rl4096train4ref
rl65536train4ref
```

with token-length filtering thresholds of:

- `4096` for `1.3B` and `6.7B`,
- `65536` for `30B`.

---

## Step 2. GRPO Optimization

Using `1.3B-e2e-sft` as the initialization model, we train `1.3B-e2e-grpo` on `rl4096train4end2end`.

This stage primarily investigates:

- the effectiveness of different reward functions and parameters setting


```bash
bash train_examples/GRPO/ref_single_machine_grpo_run.sh
```

---
# MTGRPO Stage (`trl-main`)

## Step 1. MTGRPO Training

We first train several `1.3B-e2e-mtgrpo` variants, including:

- `process_reward`
- `same_adv`

using:

- base model: `1.3B-e2e-sft`,
- dataset: `rl4096train4end2end`.

where the reward functions are refined based on the observations from the GRPO stage.

```bash
bash train_examples/MTGRPO/single_machine_mtgrpo_run.sh
```
